# Plan — Codegen-populated INDICATORS (polars_ta pattern)

Date: 2026-09-04. Status: implementation contract. Supersedes nothing — this
narrows the one adopted finding from the polars_ta review (2026-09-04) into
the existing 0.4.0 parity architecture.

## Context — what already exists (do not re-plan)

0.4.0 already shipped TA-Lib parity (`docs/plans/2026-09-04-indicator-parity.md`,
merged `628ac12`):

- `INDICATORS` = 55 names, `SQL_INDICATORS` = 58 (`uv run python -c ...` verified).
- Eager seam in `src/scanlang/compiler.py:541-590`: builders returning a
  callable (not `pl.Expr`) get pre-staged via
  `group_by(partition, maintain_order=True).map_groups(...)`, output renamed
  from the reserved `__adx` column to a unique alias.
- `src/scanlang/indicators.py:222-343` has **5 hand-written seam closures**
  (`_adx`, `_kama`, `_macd`, `_bbands(side)`, `_aroon`) — all the same shape:
  bind talib import + call args at n-bind time, return
  `(df) -> df.with_columns(pl.Series("__adx", arr).fill_nan(None))`.
- CDL patterns already use a **factory loop** (`_cdl(fn)` + `for _fn in _cdl_names(): INDICATORS.setdefault(...)`) — codegen-by-hand, 26 names from one closure.

**The gap:** adding parity wave 2 (ADXR, CMO, CCI already polars-native, MFI,
OBV, ADOSC, TRIX, STOCHRSI, ULTOSC, APO/PPO, BOP, IMI, MINUS_DI/PLUS_DI,
DX, MIDPOINT, SAR, T3, ACCBANDS narrowings, ...) means more copy-paste
closures, each differing only in (talib fn name, input columns, kwargs,
output slot). That is exactly what polars_ta's `tools/codegen_talib.py`
solves with generation instead of handwriting.

## Goal

One generator script produces the parity-wave-2 seam builders + registry
insertions from a declarative table. No new module, no runtime codegen —
**the generated output is committed source**, regenerated only when the table
changes (same contract as `scripts/gen_indicator_availability.py`).

## Non-goals (frozen)

- No IR changes: `arg_spec` stays `"expr"`/`"int"` (+ existing tuple-int
  precedent for `stoch_k`), one scalar output per name, multi-output via
  one-name-per-field.
- No new dependency. `talib` stays an optional extra.
- No lazy talib path — seam stays eager-only (map_groups has no lazy form).
- No Math Operators / Math Transform groups (IR arithmetic covers them).
- No `min_samples` knob (breaks DuckDB warm-up parity contract).

Wait — the generated file importing from `indicators.py` inverts the current
dependency. Better (and what the plan commits to):

- `_seam_builder(fn, inputs, kwargs, slot)` **lives in `indicators.py`**
  (it replaces the 5 hand closures; ~25 lines).
- The generator emits only **registry-insertion calls** + docstring table,
  appended to `indicators.py` between two markers (or a small generated
  block inside `indicators.py`). CDL keeps its loop (it already works).

Actually — simplest correct shape, settled here: **`indicators.py` keeps the
table and one factory; the generator script regenerates the *table* block
inside `indicators.py` from a spec file only when adding names**. The script
exists so wave 3 is a table edit + rerun, not closure surgery. The generated
artifact is the table block, not a module.

### 3. Registry insertion (generated block)

```python
# --- BEGIN GENERATED talib seam registrations (scripts/gen_talib_seam.py) ---
for _name, (_fn, _cols, _kw, _slot) in _TALIB_SEAM.items():
    INDICATORS.setdefault(
        _name,
        (("int",), _seam_builder(_fn, _cols, _kw, _slot), _cols),
    )
# --- END GENERATED ---
```

CDL loop stays as-is below it.

### 4. The factory (hand-written, replaces 5 closures)

```python
def _seam_builder(fn: str, inputs: tuple[str, ...], n_kw: str, kwargs: dict, slot: int | None):
    """Eager talib seam: bind call at n-bind time, per-partition map_groups.

    ``n_kw`` is the period kwarg name ("timeperiod", or "fastperiod" for
    fast/slow fns — macd precedent). See Task 0 for the pinned row shape.
    Returns a builder compatible with the apply() staging in compiler.py:
    called with (n, partition=...) it returns (df) -> DataFrame with the
    output in the reserved `__adx` column (fill_nan(None) for warm-up).
    """
    def build(n: int, partition: str):
        import talib
        call = getattr(talib, fn)
        cols = inputs

        def _apply(df: pl.DataFrame) -> pl.DataFrame:
            arr = call(*[df[c].to_numpy() for c in cols], **{n_kw: n}, **kwargs)
            if slot is not None:
                arr = arr[slot]
            return df.with_columns(pl.Series("__adx", arr).fill_nan(None))

        return _apply

    return build
```

Periodless fns (`ad`, CDL) don't take `timeperiod` — the table needs a flag
or those stay hand-written (CDL loop already covers them). Task 0 decides:
**periodless entries keep their existing builders; the table only covers
`timeperiod`-taking functions.** (smallest diff, no flag needed)

### 5. DuckDB side — no codegen needed

`SQL_INDICATORS` entries are already data-shaped
(`(arg_spec, builder, required_cols)` where builder returns a SQL fragment).
The duckdb `t_*` surface is discovered live via `duckdb_functions()`; the
existing `scripts/gen_indicator_availability.py` already regenerates the docs
table from both registries. **Plan: no duckdb codegen.** For wave-2 names
that are duckdb-supported, hand-add the SQL lowering (each is 1–3 lines
using `_tcall`/`_tcol` helpers) and the availability generator picks them up.

## Tasks

### Task 0: Pin the table shape + periodless policy — **RESOLVED (live-probed talib 0.7.1, 2026-09-05)**

**Objective:** Decide 4-tuple vs 5-field table rows and confirm periodless
fns stay out of the table.

**Files:** none (decision recorded in this plan).

**Decision 1 — row shape: 5-field flat tuple `(talib_fn, inputs, n_kw, fixed_kwargs, slot)`.**
The 4-tuple does not survive the probe: wave-2 has TWO period-binding shapes —
`timeperiod` fns (ADX, ADXR, CMO, MFI, TRIX, STOCHRSI, MIDPOINT, T3, ACCBANDS,
IMI, MINUS_DI, PLUS_DI, DX) and fast/slow fns where `n` binds to
`fastperiod` (MACD precedent; APO, PPO, ADOSC). Rather than a special case,
the period kwarg name is an explicit field. `fixed_kwargs` carries everything
else pinned (STOCHRSI: `fastk_period/fastd_period/fastd_matype`; T3:
`vfactor`; APO/PPO/ADOSC: slow period + `matype`). No nested shapes, no
`"n"`-marker strings in kwargs.

**Decision 2 — periodless policy: fns with no bindable period kwarg stay OUT
of the table** (hand-written builders, `_cdl` `_n=None` precedent). Probe
falsified two plan assumptions:
- **ULTOSC takes `timeperiod1/2/3`, not `timeperiod`** — no single n to bind;
  the three periods are semantic (7/14/28 defaults), not fast/slow. Hand-written.
- **OBV takes no period at all** (`OBV(real, volume)`) — it was listed as a
  table entry in the wave-2 sketch; it is periodless. Hand-written.
Also periodless (never were table candidates): BOP `(o,h,l,c)`,
SAR `(high, low, acceleration, maximum)`, HT_DCPERIOD/HT_DCPHASE.
CDL stays out as before.

**Decision 3 — slot map (live-probed output shapes):** scalar fns → `None`;
MACD tuple[3] → line=0; BBANDS tuple[3] → upper=0, lower=2; AROON tuple[2] →
(down, up) so up=1; STOCHRSI tuple[2] → (fastk, fastd), plan wants fastk=0;
ACCBANDS tuple[3] → upper=0, middle=1, lower=2 (3 scanlang names).
All wave-2 outputs are float — **no int-cast needed in the factory** (only
CDL/HT_TRENDMODE return ints and both stay hand-written).

**Decision 4 — generated block lands inside `indicators.py`** (no new
module) — re-affirmed, unchanged from §2.

**Observed warm-ups (deterministic 60-bar frame, first non-NaN index; n=14
unless noted) — for Task 3 parity masks:** ADX 27, ADXR 40, CMO 14, MFI 14,
TRIX 40, STOCHRSI 18 (fastk=3/fastd=3 probe), MIDPOINT 13, T3 24 (n=5),
ACCBANDS 13, IMI 13, MINUS_DI 14, PLUS_DI 14, DX 14, APO 25, PPO 25, ADOSC 9
(3/10), ULTOSC 28 (7/14/28), OBV 0, BOP 0, SAR 1, HT_DCPERIOD 32, MACD 33
(26+9), BBANDS 4, AROON 14.

### Task 2: The generator script

**Objective:** `scripts/gen_talib_seam.py` regenerates the table block in `indicators.py` from a YAML-free spec (Python dict in the script itself — the spec is the table, same as `gen_indicator_availability.py` precedent).

**Files:**
- Create: `scripts/gen_talib_seam.py`
- Modify: `src/scanlang/indicators.py` (add BEGIN/END markers around the table)

**Steps:**
1. Script reads its own `SPEC` dict (same shape as `_TALIB_SEAM`), renders

   twice, assert file unchanged both times, `git diff --exit-code` on second
   run inside a temp copy.
4. Commit `feat: add gen_talib_seam codegen script`.

## Risks / open questions

- **AROON slot order** (down, up) — already test-pinned; factory table row `slot=1` must reproduce it (Task 1 test asserts registry contract, Task 1 Step 4 exact-value tests catch a swap).
- **`fill_nan(None)` on int outputs** (CDL 0/±100, HT_TRENDMODE) — CDL stays outside the table; if wave-2 adds an int-output fn, cast to Float64 in the factory (compiler.py:587 already assumes float).
- **OBV starts at 0, not null** — talib semantic; document in availability warm-up column as 0 (not a bug).
- **Slow/fast pinned kwargs drift with duckdb defaults** — pin per-name via live probe in the parity test, not trust.
- **polars_ta's own lesson:** their wrappers carry no `.over(partition)` contract — our factory's per-partition map_groups IS the contract; the Task 2 validation gate (import + assert registry) is the guard.
